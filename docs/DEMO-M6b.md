# DEMO — M6b: Agent-Guided Trade Debrief

**Goal:** debrief a completed trade end-to-end via the 4-step interview (setup → plan → feelings → verdict) → enrichment lands on the trade → optionally emit a drill scenario from the debrief and take it immediately. Same protocol on all three LLM backends.

M6 phase C2 lands the debrief loop — the pipeline where the user's own trading writes their curriculum (PLAN-M6-TRAINING §0.3). C3 will add psychology/leak detection on top; C4 gamifies.

## Run
```bash
make dev
```

Default is `TRADEDESK_LLM=none` — the offline form backend. To use Claude:
- **`TRADEDESK_LLM=claude-cli`** — draws from your Claude Pro/Max monthly Agent SDK credit pool. Requires the `claude` binary on PATH.
- **`TRADEDESK_LLM=api`** — official `anthropic` SDK with your developer key. Requires `ANTHROPIC_API_KEY` in `.env`.

See README **Debrief LLM** section for the full "what leaves the machine" disclosure.

## Verify (click-path)

### Path A — Offline (default, no LLM)

1. Open **http://localhost:5173** → **Journal** (left nav).
2. **Import fills** if you haven't already (M3 flow) → a table of closed trades.
3. Click any trade → drawer opens. Scroll to the new **Debrief** section (below Facts).
4. Click **Debrief this trade** → navigates to **/debriefs/new/:tradeId**.
5. **Starting** state: skeleton, then the first agent turn (setup step).
6. **Active** state — because `TRADEDESK_LLM=none`, the UI renders as a **stepper** with option chips for the feelings + verdict steps:
   - **Setup:** free-text ("Saw PDH break with VWAP reclaim").
   - **Plan:** free-text. If your entry/exit contradict a stated stop, the drift flag appears as a yellow callout above the question ("stated stop 12.40, exited at 12.31 — did you move it?").
   - **Feelings:** chips — `calm`, `rushed`, `frustrated`, `revenge`, `confident`, `hesitant`. Also a free-text field below.
   - **Verdict:** chips — `setup-failed`, `failed-the-setup`, `good-loss`, `bad-win`, `clean`.
7. **Previewing** state: preview card shows verdict, feelings list, and any extracted plan. Two buttons:
   - **Save & finish** → enrichment saved to the trade; return to journal.
   - **Save & make a drill from this** → emits a scenario keyed to the trade's session/bars/tags → navigates to the drill lobby.
8. **Saved** state: summary card. If a scenario was emitted, "Take the drill" opens it in the C1 player. **Immediate loop closed** — you debriefed a real trade and can now redo the decision as a drill.

### Path B — Claude CLI (subscription)

1. `export TRADEDESK_LLM=claude-cli && make dev`.
2. Same trade → **Debrief this trade**.
3. **Active** state renders as **chat**: agent bubbles left, user bubbles right, textarea + Send (Enter to submit). Each agent question is generated by Claude with the trade's concrete facts embedded — symbol, entry, R, tags. The 4-step arc is enforced regardless.
4. If the `claude` binary is missing or fails, the provider **gracefully falls back** to the form backend per turn. The debrief still completes. `debriefs.llm_backend` stays `"claude-cli"` (operator's selection).
5. Preview / Save / Emit-scenario flow identical to Path A. Artifacts are shape-identical (`test_llm_backend_swap.py` locks this in).

### Path C — Anthropic API (developer key)

1. `export TRADEDESK_LLM=api ANTHROPIC_API_KEY=sk-ant-... && make dev`.
2. Same flow as Path B. Model is `claude-opus-4-8`, pay-per-token.
3. If `ANTHROPIC_API_KEY` is missing, POST /api/debriefs returns **HTTP 501** with a message naming the setting — the backend is selected but not configured. Set the key or flip back to `none`.

## What's the same across backends (contract)

Every backend implements the frozen `LLMProvider` Protocol (`backend/app/llm/base.py`). The persisted `Debrief` row is **schema-identical** across `none`, `claude-cli`, and `api` — only `debriefs.llm_backend` differs. `test_llm_backend_swap.py` proves this:

- Same `transcript` length (9 entries: initial agent + 4× (user + agent)) and same role/step sequence.
- Same populated field set (`plan`, `feelings`, `verdict`, `scenario_id` when requested).
- Same `DebriefArtifacts` shape from `/finish`.
- Same emitted-scenario shape (source_type='debrief', decision-point drill_type).

## What's different (by design)

Only the **conversation feel**:
- `none` — deterministic stepper. Same trade + same replies produce the same transcript. Zero data leaves the machine.
- `claude-cli` — chat. Claude paraphrases and probes; questions reference concrete trade facts. Uses your Claude Pro OAuth session.
- `api` — chat. Same paraphrasing behavior; pay-per-token billing.

## Design principles enforced

- **The user's own trading writes the curriculum** (PLAN-M6 §0.3). Every debrief-emitted scenario is authored from a real trade with real bars — no generic content.
- **LLM is optional and swappable** (§0.4). The seam is `LLMProvider`; the interview protocol is identical regardless of backend. Flip `TRADEDESK_LLM` and behavior contracts hold.
- **Credentials never leave the machine.** Verified by `test_llm_backend_swap.py::TestNoCredentialsLeakIntoRow` and `TestNoCredentialsLeakIntoLogs` — a canary API key is grepped for in every persisted row + every log line during a full debrief.
- **Read-only broker guarantee is unaffected.** Debriefs read trades and candles; nothing about the debrief flow touches order-placement code (there is none).

## API sanity

```bash
# Offline (no LLM). Works without any key.
curl -X POST http://localhost:9000/api/debriefs \
  -H 'content-type: application/json' -d '{"trade_id": 1}'

# Reply to the setup question.
curl -X POST http://localhost:9000/api/debriefs/1/turn \
  -H 'content-type: application/json' \
  -d '{"text": "Saw PDH break with VWAP reclaim above 12.40."}'

# ... /turn for plan, feelings, verdict ...

# Finish and emit a scenario from the debrief.
curl -X POST http://localhost:9000/api/debriefs/1/finish \
  -H 'content-type: application/json' -d '{"emit_scenario": true}'
# -> {"enrichment_saved": true, "verdict": "setup-failed", "scenario_id": 11}

# List debriefs for a trade.
curl "http://localhost:9000/api/debriefs?trade_id=1"
```

## Fallback + failure behavior

- **`claude-cli`, binary absent** → per-turn fallback to the form backend. Debrief completes. `llm_backend` stays `"claude-cli"` (records the selection, not the fallback path). Test: `test_claude_cli_binary_missing_falls_back_to_form_transcript`.
- **`claude-cli`, non-zero exit / timeout / non-JSON / shape mismatch** → same per-turn fallback.
- **`api`, missing key** → HTTP 501 at debrief-start, message names `ANTHROPIC_API_KEY`. No silent fallback to `none` — you selected `api` and the app respects that (fix that if you want offline: `TRADEDESK_LLM=none`).
- **`api`, network / auth / rate-limit errors** → per-turn fallback to the form backend within a debrief that's already started.

The failure taxonomy is symmetric across `claude-cli` and `api`, and never crashes the debrief flow.
